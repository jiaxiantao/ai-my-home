从页面开发走向系统级设计

前端架构与设计系统

我更看重架构是否能够支撑长期迭代，而不是一次性完成页面。对于复杂系统，我会优先解决边界、约束和复用方式，再决定组件拆分与状态流向。

Focus Highlights

  • 设计系统抽象
  • App Router 与服务端组件边界
  • 复杂状态与可维护性

Working Principles

用可组合而不是过度封装的方式建设组件体系。
让业务模型驱动视图结构，而不是被页面临时需求牵着走。
在 SSR、SEO、性能与交互灵活性之间做清晰权衡。

Deep Dive

打开一个领域后，看到的是可复用的方法与判断逻辑

每个专题都不只是技术名词，而是围绕业务复杂度、团队协作与长期维护给出的工程判断。你后续可以继续补充更多案例、文章和深入拆解。

Topic 01

组件体系设计

从原子组件到业务组件，保持复用与表达力平衡。

我的关注点

  • 组件职责是否单一且可复用
  • API 设计是否稳定、可预期
  • 样式方案是否支持主题与扩展

我更倾向把设计 token、基础组件、业务组合组件分层建设，避免所有能力都堆到一个“大而全”的组件里。

Topic 02

渲染边界与数据边界

明确哪些内容适合服务端获取，哪些适合客户端增强。

在 Next.js App Router 体系下，我会先判断：

  1. 这个模块是否依赖 SEO 与首屏可见内容
  2. 是否必须在客户端持有交互状态
  3. 数据更新频率和缓存策略是什么

这样可以减少无意义的客户端负担，同时保留良好的交互体验。

Topic 03

可扩展信息架构

让站点既适合展示，也适合持续沉淀知识内容。

我会优先把内容结构和页面关系设计清楚，再决定具体实现。现在这套 首页总览 + 领域详情页 + 结构化内容数据 的方式，后续无论继续接文章、案例、时间线还是后台录入，都不需要推翻已有结构。
